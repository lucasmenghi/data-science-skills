# Caso trabalhado: feature-brainstorm

Cenário sintético de decisão; não é resultado executado em dados reais.

## Situação e análise

Para prever demanda, propor nível recente e variação por calendário conhecido. Uma informação de estoque corrigida depois da venda não entra como se fosse disponível antes dela.

## Recomendação explicada

Restrições de privacidade e uso devem estar ligadas às fontes reais; não solicitar atributos sensíveis apenas para ampliar o espaço de busca.

## O que entregar

Backlog de hipóteses; especificações; priorização; plano de ablação.

## Como verificar

Entregar backlog de candidatos, descartes justificados e experimento mínimo; nenhuma feature é aprovada apenas pela intuição.

## Contraponto

Mais features não significa melhor produto. Se a premissa do caso mudar, reavaliar a decisão em vez de reutilizar a conclusão. Informar o que falta para passar de hipótese a evidência.
